# معماری یادبین کودک

```
core/kids  (TypeScript خالص: بدون DOM، بدون ساعت، بدون I/O)
  ├─ config      سن ← سطح پایه، سقف سخت، پارامترهای adaptive/growth/journey (قابل تنظیم)
  ├─ games/*     ۶ بازی = state machine خالص + GameSpec (۱۰ سطح هر بازی)
  ├─ scoring     metrics چندبعدی ← signal هر مهارت
  ├─ adaptive    سطح بعدی (حداکثر ±۱، سقف/کف، cooldown، fail-safe)
  ├─ growth      moving average + روند (median) + حداقل نمونه
  ├─ journey     سفر روزانه + پیشنهاد استراحت
  ├─ rewards     ستاره/XP/مدال/دنیا (فقط «من امروز در برابر من دیروز»)
  └─ report      گزارش هفتگی/ماهانه (قانون‌محور، بدون AI)
        ▲                                   ▲
        │ همان کد                           │ همان کد
  Worker (منبع حقیقت)                 Student Web (offline-first)
  /api/kids/*  + D1                   KidsEngine + IndexedDB + صف sync
```

## تصمیم‌های کلیدی
1. **هستهٔ مشترک.** منطق آموزشی فقط یک‌بار نوشته شده؛ هم روی دستگاه (آفلاین) و هم روی Worker اجرا می‌شود، پس دو نسخه هرگز از هم فاصله نمی‌گیرند. بازی‌ها state machine خالص‌اند (زمان را از بیرون می‌گیرند) و با bot قابل تست و بازپخش‌اند.
2. **Worker منبع حقیقت.** کلاینت هرگز امتیاز نمی‌فرستد؛ فقط trialهای خام. Worker با همان هسته metrics، signal، ستاره، سطح بعدی و جوایز را دوباره حساب می‌کند. بعد از هر sync، وضعیت Worker روی دستگاه می‌نشیند.
3. **Offline-first.** نتیجهٔ هر بازی اول روی دیسک (IndexedDB) نوشته می‌شود (write-ahead) و بعد ارسال؛ صف به ترتیب و با `sessionId` ایدمپوتنت ارسال می‌شود.
4. **Idempotency.** کلید `(child_id, session_id)`. همهٔ دستورهای تغییر وضعیت در یک batch D1 با شرط «این session هنوز نیست» اجرا می‌شوند و ردیف session **آخر** درج می‌شود؛ ارسال تکراری یا هم‌زمان هیچ اثری ندارد (تست race دارد).
5. **احراز هویت جدا.** والد: JWT با کلید مشتق‌شده (توکن والد هرگز در مسیرهای معلم پذیرفته نمی‌شود و برعکس). کودک: توکن مبهم `kc_…` فقط به‌صورت hash در دیتابیس؛ والد می‌تواند پیوند را بچرخاند (قبلی بی‌اثر).
6. **سن فقط نقطهٔ شروع.** سطح اولیه از سن؛ بعد از آن عملکرد مشاهده‌شده تصمیم می‌گیرد، همیشه داخل [کف، سقف] (پیش‌فرض: حداکثر یک سطح بالاتر از پایهٔ سن).
7. **سازگاری با Teacher.** فقط افزایشی: جدول‌های `kids_*`، مسیرهای `/api/kids/*`، پوشهٔ `student-web/src/kids`. یک شرط در `main.ts` (مسیر `/kids`) و یک خط در router Worker.

## توسعهٔ آینده
- بازی تازه: یک کلاس `GameInstance` + یک ورودی در `GAME_SPECS` + یک view؛ موتورهای adaptive/journey/growth تغییر نمی‌کنند.
- سطح (band) تازه یا سن بالاتر: فقط `core/kids/config.ts`.
- Core مشترک با محصول معلم: scoring فعلی معلم دست‌نخورده مانده؛ مهاجرت تدریجی به `core/` ممکن است ولی عمداً انجام نشد تا ریسک رگرسیون صفر بماند.
