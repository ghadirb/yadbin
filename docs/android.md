# اپ معلم (Android)

## ساختار
```
app/src/main/kotlin/com/yadbin/teacher/
├── core/{network,auth,database,utils}    ApiClient (OkHttp)، TokenStore (رمزنگاری‌شده)، Room، اعتبارسنجی/قالب‌بندی/QR
├── data/{remote,local,repository}        ApiService (یک تابع برای هر endpoint)، CacheStore، Repository (شبکه‌ی اول، کش هنگام آفلاین)
├── domain/{models,usecases}              مدل‌های JSON مطابق Worker، CreateActivityUseCase
└── ui/{auth,dashboard,classes,activities,reports}   صفحه‌ها + ViewModel
```

## رفتارهای مهم
- نشست: فقط JWT در EncryptedSharedPreferences؛ رمز عبور ذخیره نمی‌شود. ردشدن توکن توسط سرور (۴۰۱) → بازگشت به ورود.
- آفلاین: آخرین پاسخ موفق هر صفحه در Room ذخیره می‌شود و هنگام قطع اینترنت با نوار «اتصال اینترنت برقرار نیست…» نمایش داده می‌شود. عملیات نوشتن (ساخت کلاس، افزودن دانش‌آموز، ساخت فعالیت) نیازمند اینترنت است.
- خروج: کش پاک می‌شود تا داده‌ی معلم قبلی دیده نشود.
- اشتراک لینک: Android Share Sheet (هر پیام‌رسانی) + کپی + QR (ZXing، محلی). هیچ API اختصاصی پیام‌رسان وجود ندارد.
- «حذف از کلاس» با «حذف داده‌ها» جدا و با تأیید جداگانه است.
- گزارش: اگر `sufficientData=false` هیچ عددی نمایش داده نمی‌شود؛ نمودار روند فقط با ≥۲ جلسه؛ برچسب‌ها «عملکرد مشاهده‌شده» و «پیشنهاد سیستم»؛ رتبه‌بندی/مقایسه وجود ندارد.
- مجوزها: فقط `INTERNET`.

## تست
`gradle testDebugUnitTest` (JVM): قرارداد API با MockWebServer (هدر Authorization، خطاهای فارسی، ۴۰۱، قطع شبکه)، اعتبارسنجی موبایل/رمز/افزودن سریع، fallback آفلاین Repository، پارس JSON گزارش‌ها، QR، و نبودن واژه‌های تشخیصی در برچسب‌ها.
تست UI روی دستگاه (Espresso/Compose test) هنوز نوشته نشده است.

## UI v1.2 — مراحل بعدی (سند «ظاهر و پروفایل»)
- کارت دانش‌آموز در تب «دانش‌آموزان» (`ClassDetailScreen.kt`): آواتار، نام، پایه • سن، سه چیپ وضعیت؛ لمس کارت = ورود به پروفایل، لمس آواتار = ویرایش تصویر.
- تصویر/آواتار (`core/avatar`, `ui/common/Avatar.kt`, `AvatarEditor.kt`): فقط Local (`files/student_photos/<id>.jpg`)، ۶ آواتار خنثی رسم‌شده در کد، آواتار دختر/پسر فقط وقتی جنسیت ثبت شده و چیز دیگری انتخاب نشده؛ اولویت نمایش: عکس → آواتار انتخابی → پیش‌فرض. هیچ مجوز دوربین/حافظه لازم نیست.
- پروفایل دانش‌آموز (`StudentReportScreen.kt`): هدر با سه عدد، کارت مهارت‌ها («عملکرد اخیر»، بدون برچسب تشخیصی)، نمودار روند از ۲ نقطه به بالا (جهت RTL)، فعالیت‌های اخیر.
- فعالیت: `ActivityCard.kt` (شامل تعداد سؤال، زمان پیشنهادی، تعداد دانش‌آموز، وضعیت و نوار پیشرفت)؛ فرم ساخت فعالیت ۵ مرحله‌ای (مشخصات → هدف → مخاطب → تنظیمات → بررسی).
- حذف: «حذف کامل دانش‌آموز» تصویر محلی را هم پاک می‌کند؛ حذف از کلاس، حذف داده‌ها و حذف کلاس تصویر را نگه می‌دارند چون خود دانش‌آموز باقی می‌ماند (مطابق `docs/privacy.md`).
- هنوز انجام نشده: تست سازگاری روی دستگاه (موبایل کوچک/بزرگ، متن طولانی، دانش‌آموز/فعالیت زیاد، خروج و ورود مجدد با تصویر، آفلاین) — سند §26.

## اشتراک و خرید مایکت در اپ (v1.4)

- **صفحه‌ها:** کارت وضعیت در داشبورد ← «اشتراک من» (وضعیت، تاریخ‌ها، محدودیت‌ها و مصرف) ← «ارتقا» (پلن‌ها و خرید). همهٔ مقدارها از `GET /api/subscription` و `GET /api/plans` می‌آید؛ اپ هیچ دسترسی‌ای را خودش تصمیم نمی‌گیرد.
- **پیام سقف رایگان:** وقتی Worker خطای `FEATURE_LIMIT_REACHED` بدهد، `ApiClient` پیام فارسی سرور را به یک دیالوگ سراسری می‌دهد (با دکمهٔ «مشاهده پلن‌ها»).
- **خرید:** `core/billing/MyketBilling.kt` (کتابخانهٔ رسمی `com.github.myketstore:myket-billing-client:1.6`) و `PurchaseCoordinator`: ساخت پرداخت در سرور ← `launchPurchaseFlow(sku, developerPayload)` ← ارسال `originalJson`+`signature` به سرور ← فقط پس از `ok:true` مصرف (Consume).
- **بازیابی:** در شروع داشبورد و باز شدن صفحه‌ها، خریدهای پرداخت‌شده ولی تحویل‌نشده دوباره به سرور فرستاده می‌شوند (طبق هشدار مستندات مایکت). سرور idempotent است.
- **ساخت APK با مایکت:** `gradle assembleRelease -PMYKET_PUBLIC_KEY=<کلید عمومی از پنل مایکت>` (یا متغیر محیطی `MYKET_PUBLIC_KEY`). کلید به‌صورت XOR در `BuildConfig` ذخیره و هنگام اجرا بازسازی می‌شود. بدون کلید، خرید غیرفعال است و UI «پرداخت آنلاین به‌زودی فعال می‌شود» را نشان می‌دهد. **Access Token هرگز در اپ نیست.**
- **مجوزها:** کتابخانهٔ مایکت `ir.mservices.market.BILLING` و `<queries>` برای برنامهٔ مایکت را به manifest اضافه می‌کند (فقط برای ارتباط با مایکت).
- **پیام‌های شبکه:** «اتصال اینترنت برقرار نیست» دیگر برای هر خطایی نشان داده نمی‌شود: timeout → «سرور دیر پاسخ داد»، قطع DNS/اتصال → «ارتباط با سرور برقرار نشد…». نوع exception (و در نتیجه نمایش دادهٔ ذخیره‌شده در حالت آفلاین) تغییری نکرده است.


## حذف حساب، صفحه‌های حقوقی و گزارش خطا (v1.7)

- **حذف حساب (self-service):** معلم از «بیشتر ← حساب، پشتیبانی و حریم خصوصی» با وارد کردن رمز و تیک تأیید، حساب و **همهٔ** داده‌هایش را برای همیشه پاک می‌کند (کلاس‌ها، دانش‌آموزان، نتایج، فعالیت‌ها، آزمون‌ها، منابع کتاب، اشتراک و پرداخت‌ها، شمارنده‌های مصرف). هیچ نسخهٔ پشتیبان یا بازگشتی نگه داشته نمی‌شود؛ لینک دانش‌آموزان فوراً از کار می‌افتد. اشتراک فعال هم از بین می‌رود و بازپرداخت انجام نمی‌شود (در متن صفحه نوشته شده). جزئیات: `docs/api.md`.
- **پاک‌سازی محلی:** پس از موفقیت سرور، توکن و کش Room پاک می‌شود و `StudentAvatarStore.deleteEverything()` همهٔ تصاویر و آواتارهای انتخابی دانش‌آموزان را از حافظهٔ خصوصی اپ حذف می‌کند.
- **صفحه‌های عمومی:** `/privacy`، `/terms`، `/support` (در `student-web/public`) و لینک آن‌ها در اپ. متن‌ها پیش‌نویس‌اند و پیش از انتشار باید مشاور حقوقی ببیندشان.
- **گزارش خطای محلی (بدون SDK):** `CrashLog` آخرین کرش را فقط به‌صورت نام کلاس‌های exception، stack frame و نسخهٔ اپ/دستگاه در حافظهٔ خصوصی ذخیره می‌کند؛ **پیام exception هرگز ذخیره نمی‌شود** (ممکن است متن کاربر داشته باشد). چیزی خودکار ارسال نمی‌شود؛ معلم در صفحهٔ حساب می‌تواند آن را با «ارسال گزارش» برای پشتیبانی بفرستد یا پاک کند.
- **پشتیبانی:** `@MaliarProSupport` در تلگرام، روبیکا و ایتا (`core/utils/Support.kt`).
- **ساخت و انتشار:** `versionName` از `VERSION_NAME` (پیش‌فرض `1.0.0`)؛ `proguardFiles` ثبت است ولی R8 فقط با `MINIFY=true` روشن می‌شود. چک‌لیست: `docs/release.md`.
