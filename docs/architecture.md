# معماری

- **Worker** یک Router سبک دارد (`worker/src/index.ts`). مسیرهای معلم با JWT (HS256) محافظت می‌شوند؛ مسیرهای `/api/play/*` فقط با توکن تصادفی ۸۰ بیتی کار می‌کنند.
- **مالکیت داده**: هر query معلم با `teacher_id` فیلتر می‌شود؛ شناسه‌ی متعلق به معلم دیگر مثل «یافت نشد» (404) رفتار می‌کند.
- **Scoring** ماژول خالص (`worker/src/scoring`) است، بدون I/O و بدون AI؛ برای افزودن AI Summary بعداً، خروجی `GameAggregate` ورودی مناسبی است.
- **Game Engine مستقل از Question Bank**: سرور `pools` سؤال (هر سطح یک pool) می‌دهد؛ بازی سمت کلاینت بر اساس آن اجرا می‌شود.
- **Local-first**: در شروع یک GET، در پایان یک POST. توالی سؤال‌ها از `seed = session id` ساخته می‌شود، پس Resume همان سؤال‌ها را می‌دهد.
- **Idempotency**: `game_results.session_id` کلید اصلی است + `INSERT OR IGNORE`؛ ارسال تکراری/هم‌زمان فقط یک نتیجه می‌سازد.
- **درستی جواب «راهش را پیدا کن»** در سرور از روی سؤال‌های همان session محاسبه می‌شود (کلاینت نمی‌تواند نمره را جعل کند). برای بازی حافظه/توجه سرور فقط بازه و ساختار رویدادها را اعتبارسنجی می‌کند (مرز شناخته‌شده‌ی معماری Local-first).
- **Remove ≠ Delete**: حذف از کلاس فقط `removed_at` را می‌گذارد؛ حذف داده (`DELETE /api/students/:id`) همه‌ی نتایج را پاک می‌کند.
